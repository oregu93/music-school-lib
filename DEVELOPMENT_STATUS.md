# Состояние разработки

Обновлено: 29 сентября 2026 года.

## Рабочий статус

MLC находится в production и используется через основной пользовательский адрес:

```text
https://mlc-vercel-access.vercel.app/
```

Production backend:

```text
https://music-school-library.oregu93.workers.dev/
```

Vercel работает как внешний access gateway к тому же production Worker/D1; отдельной копии каталога на Vercel нет.

## Реализовано и принято

- production/staging разделены;
- контролируемый deployment с identity check;
- Yandex OAuth + PKCE + server-side sessions;
- whitelist пользователей и роли;
- поиск по каталогу;
- порционная загрузка / infinite scroll;
- фиксированный заголовок таблицы;
- сортировка по автору/заглавию и последним изменениям в обоих направлениях;
- мобильный focused-search над экранной клавиатурой;
- полная карточка экземпляра;
- авторасширяемые текстовые поля;
- добавление карточки с необязательной основой из похожей записи;
- редактирование;
- отметка «Проверено»;
- выдача/возврат и история операций;
- восстановимое удаление и корзина;
- инвентаризация с явным включением режима;
- экспорт каталога;
- локальный IndexedDB outbox для ожидающих изменений;
- автоматический replay после восстановления связи;
- server-side revision conflicts;
- идемпотентные operation IDs;
- аудит изменений;
- резервное копирование D1 и CSV;
- публичная help-страница для библиотекаря;
- Vercel access gateway как обход ограничений доступа к `workers.dev` на рабочем месте.

## Канонические данные

Исходный каталог был перенесён из MARC/Excel в D1.

Основной пользовательский идентификатор экземпляра:

```text
inventory_number
```

`db_number` сохраняется как legacy/source identifier.

Исторические `inventory_number` могут повторяться и намеренно не имеют UNIQUE-ограничения.

## Ближайшие задачи

Актуальный список ведётся в [docs/ROADMAP.md](docs/ROADMAP.md).

На текущий момент среди оставшихся задач:

- `LIBRARIAN_UX-003` — сканирование штрихкода/QR камерой телефона;
- `LIBRARIAN_UX-014` — убрать «№ записи в БД» из пользовательского списка категорий поиска, сохранив техническую поддержку;
- `AUTH-SESSION-002` — завершение сессии после двух часов отсутствия активности;
- `OPERATIONS-002` — отдельный acceptance USB-сканера;
- `PLATFORM-001/002` — дальнейшее PWA/offline/cross-platform hardening.

## Неподлежащие изменению правила

- production не используется для разработки;
- schema changes проходят через versioned migrations;
- production deployment выполняется только после staging acceptance;
- резервные исходные файлы не модифицируются автоматически;
- реальные персональные данные, secrets и production exports не помещаются в Git;
- текущий hosting не должен становиться необратимой vendor-зависимостью.
