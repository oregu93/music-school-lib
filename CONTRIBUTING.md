# Участие в разработке MLC

MLC развивается как открытый проект для библиотечных сценариев.

## Перед началом

Для значимого изменения:

1. прочитайте `README.md`, `ARCHITECTURE_RULES.md` и `docs/ARCHITECTURE.md`;
2. проверьте актуальный `docs/ROADMAP.md`;
3. не используйте production как среду разработки;
4. сохраняйте путь `local -> staging -> production`.

## Локальная проверка

Перед pull request или предложением к выпуску:

```bash
pnpm install
pnpm launch:check
```

Изменения базы выполняются только versioned migrations.

## Совместимость

Предпочтительны:

- обратно совместимые API;
- additive migrations;
- явные migration/rollback assumptions;
- отсутствие vendor lock-in в бизнес-логике;
- кроссплатформенный browser-first подход.

## Данные и приватность

Запрещено коммитить:

- реальные каталожные выгрузки библиотек;
- production D1 exports;
- Excel/CSV/SQL с рабочими данными;
- реальные имена, email и UID сотрудников;
- OAuth/session tokens;
- `.dev.vars`, приватные `.env`, ключи и сертификаты.

Для тестов используйте только синтетические данные.

## Стиль изменений

Pull request должен по возможности содержать:

- краткое описание проблемы;
- описание решения;
- сведения о проверке;
- указание на migration, если схема менялась;
- обновление документации, если изменяется пользовательское поведение или архитектура.

## Лицензия вкладов

Предлагая код или документацию в проект, участник соглашается, что его вклад может распространяться как часть MLC на условиях **AGPL-3.0-or-later**.

Если вклад включает код третьих лиц, его происхождение и лицензия должны быть явно указаны и совместимы с лицензированием проекта.
