# Политика безопасности

## Сообщение об уязвимости

Не публикуйте сведения об активной уязвимости, credentials, персональных данных или production-конфигурации в публичном issue.

До появления отдельного security contact используйте приватный GitHub-канал владельца репозитория или заранее согласованный частный способ связи.

## Что считать чувствительными данными

К ним относятся, в частности:

- OAuth/session tokens;
- приватные ключи и секреты;
- содержимое `.dev.vars` и приватных environment-файлов;
- production database exports;
- реальные данные пользователей и сотрудников;
- внутренние сведения, позволяющие получить несанкционированный доступ.

OAuth Client ID и Cloudflare D1 database ID являются идентификаторами, а не credentials, однако сами по себе они не должны сопровождаться секретными значениями.

## Что приложить к сообщению

Достаточно:

- описание проблемы;
- затронутый компонент;
- минимальные шаги воспроизведения;
- предполагаемое влияние;
- версия/commit, где проблема наблюдается.

Не прикладывайте рабочие библиотечные данные, если они не нужны для воспроизведения.

## Исправления

Security fixes должны проходить обычные проверки проекта, но публикация технических подробностей может быть отложена до выпуска исправления.
