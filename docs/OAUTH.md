# Вход и выход

## Текущий закрытый сайт

Sites выполняет вход до открытия каталога и передаёт серверу подтверждённый идентификатор и email пользователя. API не доверяет данным из браузера и повторно проверяет пользователя. Выход выполняется переходом на:

```text
/signout-with-chatgpt?return_to=/
```

## Самостоятельный сайт с Яндекс ID

Нужны четыре серверных адреса:

- `GET /auth/yandex/login` — создаёт `state`, PKCE verifier и перенаправляет на Яндекс;
- `GET /auth/yandex/callback` — проверяет `state`, меняет code на токен на сервере и создаёт сессию;
- `POST /auth/logout` — завершает серверную сессию и удаляет cookie;
- `GET /api/session` — возвращает только безопасные сведения о текущем пользователе.

Обязательные меры:

1. OAuth Authorization Code Flow с PKCE, `state` и одноразовым callback.
2. Токены Яндекса хранятся только на сервере, не в `localStorage` и не в журналах.
3. Браузер получает только cookie `HttpOnly; Secure; SameSite=Lax`.
4. Доступ разрешается только Yandex ID или email из серверного белого списка.
5. Все операции изменения повторно проверяют сессию и роль на сервере.
6. `YANDEX_CLIENT_SECRET` и `SESSION_SECRET` задаются в секретах хостинга.

Файл `.env.example` содержит только имена настроек. Реализацию адаптера Яндекс OAuth следует добавлять после выбора окончательного хостинга и callback-домена; текущие маршруты Sites при этом не смешиваются с внешним OAuth.
