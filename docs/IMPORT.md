# Проверка и загрузка каталога

## Правила

- `library_catalog_complete_0.xlsx` — неизменяемая резервная копия;
- импорт выполняется из `library_catalog_complete.xlsx`;
- перед загрузкой сверяются число строк, названия листов и контрольные поля;
- подготовленные SQL/JSON-файлы содержат библиотечные данные и не отправляются в Git.

## Локальная проверка

```powershell
python scripts/catalog_to_sql.py ..\outputs\library_catalog_complete.xlsx --check-only
```

Ожидаемый ориентир текущей версии: 10 924 записи листа «Каталог» и 880 записей листа «Выдачи». В каталоге сейчас две записи без № БД и нет повторяющихся непустых № БД. Скрипт проверяет эти показатели заново при каждом запуске.

## Подготовка SQL для собственной D1

```powershell
python scripts/catalog_to_sql.py ..\outputs\library_catalog_complete.xlsx --output private-data\library.catalog-import.sql
```

По умолчанию существующие строки не удаляются. Ключ `--replace` добавляет очистку таблиц и допустим только после резервного копирования рабочей базы.

Подготовленный файл применяют к выбранной D1 через Wrangler. Сначала используйте локальную или тестовую базу, затем сравните количество записей и несколько карточек с Excel.

## Текущий закрытый Sites

Управляемая база Sites не загружается через обычный Wrangler. Для неё будет добавлен отдельный защищённый экран импорта с проверкой администратора, предварительным отчётом и подтверждением. До появления этого экрана полный каталог на Sites не передаётся.

## Соответствие двух спорных полей

- исходное поле `Инвентарный номер` → `№ записи в БД`;
- исходное поле `Штрихкод (852$p)` → `Инвентарный номер`.
